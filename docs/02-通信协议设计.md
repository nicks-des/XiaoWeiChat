# 02 通信协议设计

> 版本：v1.0 ｜ 适用于：客户端↔ChatServer 长连接、服务间自研 RPC、信令面。
> HTTP API（注册/登录/文件）不在本文档，见 01 文档 §3.1/§3.4 与 06 文档对应任务。

---

## 1. 传输帧格式（二进制，大端序）

所有 TCP 通道（客户端长连接、服务间 RPC）复用同一帧格式，解决 TCP 粘包/拆包：

```
偏移  长度  字段          说明
0     4    totalLength   整帧长度（含帧头），范围 [12, 16MB]
4     2    msgId         消息/信令 ID（见 §2 分配表）
6     1    version       协议版本，当前 = 1
7     1    flags         bit0: 压缩(zstd 预留)  bit1: Push(服务端主动推)  bit2: 加密(预留)
8     4    pktSeq        包序号：请求-响应匹配与日志追踪（客户端/发起方自增，响应回填同值）
12    N    body          Protobuf 编码的消息体
```

设计要点（面试高频）：

1. **定长头 + 长度字段**是粘包处理的标准解；接收侧 `BufReader` 先凑齐 12 字节头 →
   解出 totalLength → 再凑齐剩余 body，半包/多包均正确处理；
2. `pktSeq`（帧头）与会话消息的 `convSeq`（body 内）是**两个不同概念**：前者是传输层
   请求匹配序号，后者是业务可靠性序号（见 §4）；
3. 心跳帧：`msgId=0x0000`，body 为空。

## 2. msgId 分配表（按 0x0100 分段）

### 0x00xx 系统

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0000 | Heartbeat | 双向 | 空体；30s 周期，90s 无响应判死 |

### 0x01xx 登录鉴权

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0101 | LoginRequest | C→S | uid + token + 设备信息 |
| 0x0102 | LoginResponse | S→C | 结果 + 服务器时间 + 待同步任务 |
| 0x0103 | LogoutRequest | C→S | 主动登出 |
| 0x0104 | KickNotice | S→C | 顶号：同账号他处登录，携带登录地点/时间 |
| 0x0105 | ReconnectRequest | C→S | 断线重连：uid + token + 各会话本地最大连续 seq |

### 0x02xx 好友

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0201 | FriendSearchRequest / Response | C↔S | 按 uid/用户名搜索 |
| 0x0202 | FriendApplyRequest | C→S | 好友申请（附验证消息） |
| 0x0203 | FriendApplyNotice | S→C | 推送给被申请方 |
| 0x0204 | FriendApplyHandleRequest | C→S | 同意/拒绝 |
| 0x0205 | FriendApplyResultNotice | S→C | 处理结果推给申请方（同意时附带对方资料+新建会话） |
| 0x0206 | FriendDeleteRequest | C→S | 删除好友（双向删除） |
| 0x0207 | FriendListRequest / Response | C↔S | 全量好友列表（含分组、备注） |
| 0x0208 | FriendUpdateNotice | S→C | 好友资料/在线状态变更 |

### 0x03xx 单聊与会话

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0301 | MessageSendRequest | C→S | 通用消息发送（单聊/群聊/AI 共用，见 §3） |
| 0x0302 | MessageAck | S→C | 服务端已落库：回填 convSeq |
| 0x0303 | MessageNotify | S→C | 新消息推送 |
| 0x0304 | MessageReadAck | C→S | 已读上报（convId + lastReadSeq） |
| 0x0305 | MessageReadNotice | S→C | 对端已读推送 |
| 0x0306 | MessageRecallRequest | C→S | 撤回（2 分钟内；服务端校验） |
| 0x0307 | MessageRecallNotice | S→C | 撤回广播 |
| 0x0308 | SyncRequest | C→S | 漫游同步：各会话本地最大连续 seq 摘要 |
| 0x0309 | SyncResponse | S→C | 差量消息批（分页，hasMore + cursor） |
| 0x030A | ConversationListRequest / Response | C↔S | 会话列表（含未读数、最后一条） |
| 0x030B | TypingNotice | 双向 | 「对方正在输入」（AI 侧为打字机前置信号，不落库） |

### 0x04xx 群组

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0401 | GroupCreateRequest / Response | C↔S | 建群（初始成员） |
| 0x0402 | GroupInviteRequest | C→S | 邀请入群（可带确认） |
| 0x0403 | GroupJoinNotice | S→C | 入群广播（附成员列表增量） |
| 0x0404 | GroupQuitRequest | C→S | 退群 |
| 0x0405 | GroupKickRequest | C→S | 踢人（群主/管理员） |
| 0x0406 | GroupDissolveRequest | C→S | 解散（群主） |
| 0x0407 | GroupInfoRequest / Response | C↔S | 群资料/成员列表 |
| 0x0408 | GroupUpdateNotice | S→C | 群资料变更广播 |

### 0x05xx 文件（元数据信令；字节流走 HTTP，见 ADR-007）

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0501 | FileTransferNotice | S→C | 文件消息内的 fid 下载地址解析（可选加速） |
| 0x05F0 | — | — | 预留：P2P 直传协商 |

### 0x06xx 音视频通话（详见 05 文档）

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0601 | CallInviteRequest | C→S | 发起通话（audio/video + 预置 SDP offer） |
| 0x0602 | CallRingNotice | S→C | 被叫振铃 |
| 0x0603 | CallAcceptRequest | C→S | 接听（回 SDP answer） |
| 0x0604 | CallRejectRequest | C→S | 拒绝/占线 |
| 0x0605 | CallCancelRequest | C→S | 主叫取消（未接通前） |
| 0x0606 | CallHangupRequest | C→S | 挂断（含通话时长，服务端写通话记录） |
| 0x0607 | CallSdpNet | 双向经S中转 | ICE 协商后的 SDP 重协商 |
| 0x0608 | CallIceNet | 双向经S中转 | ICE candidate 交换 |
| 0x0609 | CallStateNotice | S→C | 通话状态变化（超时未接、异常挂断） |

### 0x07xx 酒馆 / AI（详见 04 文档）

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0701 | AiStreamChunkNotice | S→C | 流式分片：convId + targetSeq(预占) + delta 文本 |
| 0x0702 | AiStreamEndNotice | S→C | 流式结束：最终全文、usage、好感度增量、finishReason |
| 0x0703 | AiStreamErrorNotice | S→C | 生成失败/超时（附兜底文案） |
| 0x0704 | AiSwipeRequest | C→S | 重掷：regenerate / next / prev |
| 0x0705 | AiSwipeResponse | S→C | 新版本内容（追加进 versions） |
| 0x0706 | AiCharacterCardMsg | 走通用消息 | 角色卡名片消息（msgType=card），复用 0x03xx 管线 |

> AI 生成的最终消息本身走 0x0303 MessageNotify 送达（from_uid = AI 角色 uid），
> 0x07xx 仅承载流式过程与重掷信令——**AI 是普通消息管线的一等公民**（ADR-011）。

### 0x08xx 系统通知

| msgId | 名称 | 方向 | 说明 |
| --- | --- | --- | --- |
| 0x0801 | SystemNotice | S→C | 通用系统通知（公告、审核结果等） |
| 0x0802 | FriendStateNotice | S→C | 好友上线/下线/状态变更 |

## 3. Protobuf 核心定义（proto/ 目录，节选定稿）

```protobuf
syntax = "proto3";
package lingxi;

/* ========== 登录鉴权 ========== */

/** 登录请求：token 由 GateServer 登录接口下发 */
message LoginRequest {
  int64  uid            = 1;  ///< 用户 ID
  string token          = 2;  ///< 访问令牌（HMAC）
  string device_id      = 3;  ///< 设备标识（顶号判定依据）
  string client_version = 4;  ///< 客户端版本号
}

/** 登录响应 */
message LoginResponse {
  int32  err_code    = 1;  ///< 0 成功；401 token 失效；403 顶号踢出
  string err_msg     = 2;
  int64  server_time = 3;  ///< 服务器毫秒时间戳（客户端校时）
}

/* ========== 消息收发（单聊/群聊/AI 通用） ========== */

/** 消息类型枚举（与 JSON 信封结构一一对应，见 §3.2） */
enum MsgType {
  MSG_NONE     = 0;  ///< 占位
  MSG_TEXT     = 1;  ///< 文本
  MSG_IMAGE    = 2;  ///< 图片
  MSG_VOICE    = 3;  ///< 语音
  MSG_VIDEO    = 4;  ///< 视频
  MSG_FILE     = 5;  ///< 文件（word/pdf/md 等）
  MSG_SYSTEM   = 6;  ///< 系统消息
  MSG_NARRATION = 7; ///< 剧情旁白（酒馆，from_uid=0）
  MSG_CARD     = 8;  ///< 角色卡名片（酒馆）
  MSG_OOC      = 9;  ///< 玩家 OOC 发言（酒馆剧情群）
}

/** 通用消息发送/接收体 */
message MsgBody {
  int64  conv_id       = 1;  ///< 会话 ID（服务端建会话时分配的雪花 ID）
  int64  from_uid      = 2;  ///< 发送者 uid（旁白=0）
  int64  conv_seq      = 3;  ///< 服务端分配的会话内单调递增序号（客户端发送时=0）
  string client_msg_id = 4;  ///< 客户端幂等 ID（UUID）
  int32  msg_type      = 5;  ///< MsgType
  int64  send_time_ms  = 6;  ///< 发送毫秒时间戳
  bytes  payload       = 7;  ///< JSON 信封（按 msg_type 解释，见 §3.2）
  int32  status        = 8;  ///< 0 正常；1 已撤回；2 生成中(AI)；3 被截断
}

/** 发送请求 */
message MessageSendRequest {
  MsgBody body = 1;
}

/** 发送确认：服务端落库成功后回执 */
message MessageAck {
  int32  err_code    = 1;
  int64  conv_id     = 2;
  string client_msg_id = 3;  ///< 与请求对应
  int64  conv_seq    = 4;    ///< 服务端分配的会话序号
  int64  send_time_ms = 5;
}

/** 新消息推送 */
message MessageNotify {
  MsgBody body = 1;
}

/** 漫游同步：客户端上报各会话本地最大连续 seq */
message SyncRequest {
  repeated ConvCursor cursors = 1;  ///< 每个活跃会话一条
}

message ConvCursor {
  int64 conv_id  = 1;
  int64 last_seq = 2;  ///< 本地已连续收到的最大 seq
}

/** 漫游同步响应（分页） */
message SyncResponse {
  repeated MsgBody messages = 1;
  bool  has_more = 2;
  int64 next_cursor = 3;  ///< 下一页查询游标（服务端内部游标编码）
}
```

```protobuf
/* ========== 酒馆流式与重掷（节选） ========== */

/** AI 流式分片 */
message AiStreamChunkNotice {
  int64  conv_id    = 1;
  int64  target_seq = 2;  ///< 本条 AI 消息预占的会话 seq（生成完成前 status=2）
  string delta_text = 3;  ///< 增量文本
}

/** AI 流式结束 */
message AiStreamEndNotice {
  int64  conv_id        = 1;
  int64  target_seq     = 2;
  string final_text     = 3;  ///< 最终全文（分片可能乱序/丢失，以本字段为准）
  int32  finish_reason  = 4;  ///< 0 stop 1 length 2 error-truncated
  int32  affinity_delta = 5;  ///< 好感度增量（仅 AI 单聊/剧情群有意义）
}

/** Swipe 重掷请求 */
message AiSwipeRequest {
  int64  conv_id = 1;
  int64  conv_seq = 2;  ///< 目标 AI 消息 seq
  int32  action  = 3;   ///< 0 重新生成(替换当前) 1 下一版本 2 上一版本
}
```

其余（好友/群/通话）消息结构同风格，随对应里程碑落地并同步更新本表。

## 4. 消息可靠性设计（不丢、不重、不乱序）

| 编号 | 规则 | 机制 |
| --- | --- | --- |
| R1 | 先落库，后投递 | 服务端收到消息 → 幂等检查 → 分配 seq 并落 MySQL → 才 ACK 与推送；服务崩溃不丢已 ACK 之外的消息 |
| R2 | 不重 | 发送侧重试携带同一 clientMsgId；服务端 `dedup:{convId}:{clientMsgId}`（Redis, TTL 24h）+ MySQL 唯一键双保险 |
| R3 | 不乱序 | 会话内以 convSeq 排序渲染；客户端发现 seq 空洞 → 立即对该会话发起增量补拉 |
| R4 | 不丢（离线/弱网） | 上线/重连发 SyncRequest（各会话 lastSeq 游标）→ 服务端差量补拉（分页） |
| R5 | ACK 语义 | MessageAck = 服务端已持久化（非「对端已读」）；对端已读走独立的 0x0304/0x0305 |
| R6 | seq 权威性 | seq 只由服务端分配（Redis INCR），客户端任何本地序号不参与可靠性判定 |
| R7 | AI 流式可靠性 | 分片仅体验用；最终全文以 AiStreamEnd 为准重写本地消息；生成中(status=2)消息崩溃可由服务端重启任务续写或标记失败 |
| R8 | 时钟 | 展示时间以服务器 send_time_ms 为准，客户端仅做本地未送达消息的临时排序 |

**seq 一致性**：Redis INCR 先行、MySQL `(conv_id, seq)` 唯一键兜底——若 INCR 后落库冲突
（极端并发/Redis 回档），以 MySQL 现值+1 重新分配并告警；详见 03 文档 §3.4。

## 5. 心跳、重连与顶号

- 心跳：30s 一帧空 Heartbeat；服务端 90s 无任何帧判死并清理连接与路由；
- 重连：指数退避（1s ×2 上限 60s，±20% 抖动）；连上后先 ReconnectRequest（0x0105，免重新走 Gate），
  token 有效则复用会话并触发 SyncRequest 补拉；
- 顶号：登录成功时查 `route:uid` 若已有旧连接 → RPC KickUid → 旧端收 0x0104 强制下线；
  策略为**单设备登录**（桌面端定位，多端策略 M8 评估）。

## 6. 安全设计

1. **token**：HMAC-SHA256（`uid.expire.signature`），密钥仅 StatusServer/Gate 持有；ChatServer 经 RPC 校验；
2. **防重放**：HTTP 接口要求 `timestamp + nonce`（5 分钟窗口，nonce 入 Redis 去重）；
3. **传输加密**：首期内网明文 + flag 预留；公网部署时启用 TLS（Asio ssl_stream / Beast ssl）——
   客户端协议层已按可替换设计；
4. **越权校验**：所有会话操作服务端校验「uid ∈ 会话成员」；文件下载鉴权 fid+token 短时效签名 URL；
5. **内容安全**：文本消息服务端敏感词过滤；AI 输入输出双端审核（见 04 文档 §9）。

## 7. 版本兼容策略

- 帧头 version 字段：客户端与各服务端启动时握手校验主版本；
- proto3 规则：只增不改不删字段编号；废弃字段标 `[deprecated = true]` 保留编号；
- JSON 信封：新字段可加不可删，未知字段客户端必须忽略（向前兼容）；
- 消息 ID 表只追加不复用，废弃号段标注。
