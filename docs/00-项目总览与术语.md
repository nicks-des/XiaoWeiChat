# 00 项目总览与术语

> 版本：v1.0 ｜ 日期：2026-10-05 ｜ 状态：已评审（四项关键决策已由项目负责人确认）

---

## 1. 项目背景与目标

### 1.1 背景

现有市场主流 IM（QQ、微信）功能成熟但封闭。「酒馆」（SillyTavern）代表的开源 AI 角色扮演
玩法正快速流行，但它是一款独立工具，与真实社交关系链是割裂的。本项目要把二者融合：
**让 AI 角色以"联系人"的身份生活在 IM 里**，用户在同一套好友 / 会话 / 消息体系中既能和真人聊天，
也能和 AI 角色进行沉浸式角色扮演。

### 1.2 项目目标

1. 实现市场常见 IM 的核心能力（对标 QQ）：
   - 账号体系：注册、登录、token 鉴权、顶号踢出；
   - 好友管理：搜索、申请、同意、删除、备注、分组；
   - 群组：建群、邀请、退群、踢人、群消息、群通知；
   - 聊天：文字、语音、图片、视频、文件（word/pdf/md 等）、表情、撤回、离线消息、多端漫游同步；
   - 音视频通话：1v1 语音 / 视频通话（多人通话作为后期扩展）。
2. 融合酒馆玩法（模块代号 Tavern，四大玩法首期全做、分期交付）：
   - 角色卡 + 世界书（兼容 SillyTavern PNG 卡 V2 规范）；
   - 剧情群聊 + 导演调度（多 AI 角色 + 玩家同群演绎）；
   - 长期记忆 + 好感度 / 状态系统；
   - Swipe 重掷 + AI 语音消息（TTS）。
3. 工程目标：
   - 服务端为分布式多节点架构，可水平扩展；
   - 协议层平台无关（Protobuf），客户端分层解耦，为后期 Android 端复用打基础；
   - 全套开发文档、测试记录、面试题沉淀（应对 IM 面试）。

### 1.3 明确不做（Non-Goals，首期）

| 不做 | 理由 | 预留 |
| --- | --- | --- |
| 万人级大群 / 直播群 | 复杂度高，非核心 | 群消息读写扩散设计留演进文档 |
| 多人音视频（SFU） | M5 先交付 1v1 | 协议与媒体层预留多端扩展 |
| 端到端加密（E2EE） | 影响服务端审核与漫游 | 传输 TLS 与存储加密先做 |
| Android 端实现 | 前期专注桌面 | 协议/分层保证可迁移，M8 出评估文档 |
| 文生图（AI 画图） | 依赖外部服务 | Tavern 的 Provider 抽象预留 |
| 本地模型后端 | 已确认 OpenAI 兼容 API 优先 | LLM 网关 Provider 抽象预留 |

## 2. 使用场景（用户故事）

1. **真人社交**：A 注册账号 → 搜索 B → 好友申请 → B 同意 → 单聊文字/图片 → 语音通话。
2. **AI 陪伴**：A 在「广场」看到角色「白露」→ 查看角色卡名片 → 添加为好友 → AI 发来开场白 →
   流式打字机回复 → 长聊后系统生成记忆摘要，AI 记得早前约定 → 好感度从「陌生」升到「信赖」。
3. **剧情演绎**：A 创建「剧情群」拉入 3 个 AI 角色 → 发一句行动 → 导演调度「剑客」先回话，
   旁白描述场景 → A 用 OOC（括号）指令暂停剧情调整设定。
4. **重掷**：AI 回复不满意 → 左滑 Swipe → AI 给出另一个版本 → 在版本间来回切换。
5. **文件协作**：把 500MB 的 pdf 拖进聊天 → FileServer 秒传/分块续传 → 对方收到卡片消息点击下载。

## 3. 术语表

| 术语 | 含义 |
| --- | --- |
| GateServer | 接入网关，只负责 HTTP 注册/登录，登录后下发 ChatServer 地址与 token |
| StatusServer | 注册中心 + 登录态服务：签发/校验 token、维护服务注册表、分配最优 ChatServer |
| ChatServer | 消息核心节点：持有客户端 TCP 长连接，处理消息/好友/群/通话信令 |
| FileServer | 文件节点：分块上传、秒传、下载、缩略图（HTTP） |
| AIServer | 酒馆节点：Prompt 组装、LLM 网关调用、世界书/记忆/导演/TTS，仅 RPC 接入 |
| uid / gid | 用户 ID / 群 ID（雪花算法生成，全局唯一） |
| conv / conv_id | 会话（单聊、群聊、AI 单聊、剧情群）及其唯一 ID |
| seq | 会话内服务端单调递增消息序号，可靠性模型的基石 |
| clientMsgId | 客户端生成的消息幂等 ID（UUID），用于去重 |
| Swipe | 酒馆玩法：同一条 AI 消息的多个候选回复版本，可左右切换 |
| 角色卡 | AI 角色的完整设定包（PNG 内嵌 JSON），兼容 SillyTavern V2 规范 |
| 世界书 Lorebook | 关键词触发的设定词条库，按需注入 Prompt，节省 token |
| 导演 Director | 剧情群聊中决定「下一个谁发言、说什么节奏」的调度器 |
| OOC | Out Of Character，玩家用括号发出的「跳出角色」的元指令 |
| TTS / ASR | 语音合成 / 语音识别 |
| simbot | 项目自研的协议模拟客户端（压测与自动化测试用） |

## 5. 风险清单与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| Qt 5.12 + MSVC 版本兼容 | 编译失败 | Qt 5.12.11 官方 msvc2017 套件与 VS2019/2022 ABI 兼容（v14x），M0 第一天即验证编译链 |
| libdatachannel 在 Windows 构建复杂 | M5 延期 | 用 vcpkg 安装（自带 opus/srtp 依赖），M4 结束即预研 |
| LLM API 不稳定 / 限流 | AI 回复失败 | 网关层重试 + 多 Provider 降级 + 队列削峰 + 超时兜底文案 |
| 消息可靠性 bug（丢/重/乱序） | 核心体验 | 可靠性模型先行设计（见 02 文档），simbot 自动化回归用例覆盖 |
| 自研 RPC 工作量超预期 | M2 延期 | RPC 只做最小集（注册/发现/调用/推送），不做跨语言、不做流控 |
| MySQL 消息表膨胀 | 查询变慢 | 首期单表+索引，分表/归档方案写入 03 文档演进章节 |
| LLM 生成内容合规 | 合规风险 | 双向内容过滤（输入敏感词 + 输出审核 Provider），分级开关 |

## 6. 交付物清单

- `client/` Qt5 桌面客户端（Windows 优先）
- `server/` gateserver / statusserver / chatserver / fileserver / aiserver + common 公共库
- `proto/` Protobuf 协议定义（平台无关，Android 端直接复用）
- `tools/` simbot 压测机器人、协议模拟脚本、部署脚本
- `docs/` 全套设计文档 + 测试记录 + 面试题库 + 开发日志
- 测试记录：单元测试随代码（gtest），联调/压测记录归档 `docs/tests/`
