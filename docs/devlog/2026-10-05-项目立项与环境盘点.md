  库 `lingxi`（utf8mb4）已建。

### 重大坑：本机代理 + schannel 吊销检查（记录 5 次失败根因）
1. vcpkg 默认读 **Windows IE 代理**（注册表 127.0.0.1:7890，clash 类软件）；
2. 所有 TLS 下载报 `curl (35) SSL connect error`——根因是 **schannel 的证书吊销检查
   （CRYPT_E_NO_REVOCATION_CHECK）** 经代理时无法完成；
3. 修复：系统 curl 一律加 **`--ssl-no-revoke`**；vcpkg 侧双管齐下——
   - 工具（cmake/ninja/powershell-core/7zip）**手动预下载**进 `downloads/`（文件名须与
     `scripts/vcpkg-tools.json` 的 archive 字段完全一致，vcpkg 会校验 sha512）；
   - **port 源码**走 `X_VCPKG_ASSET_SOURCES="x-script,curl --ssl-no-revoke -x http://127.0.0.1:7890
     -L --fail --retry 3 {url} -o {dst}"`（注意：x-script 模板是逗号分隔的**单个参数**，
     不能带尾部行为参数；且**工具下载不走资产缓存**，只有 port 走）；
4. `X_VCPKG_ASSET_SOURCES` 与 `HTTP_PROXY` 已写入 `tools/scripts/env.*` 备查。

### 其他坑
- **MySQL Connector C++ 8.3 缺 release 库**：`lib64/vs14/` 只有 debug 有 mysqlcppconn.lib，

## 2026-10-05 M1 实施记录（T10-01 ~ T10-09 服务端全链路）

### 交付
- **common 新增**：RpcFrame（RPC 帧头 9B）、RpcServer（strand 写队列 + 线程池处理器）、
  RpcClientPool（独立 IO 线程 + 空闲缓存 + requestId 匹配 + 超时重试）、
  HttpServer（Beast 异步 + 路由表 + IP 滑动窗口限流挂接）、Crypto（OpenSSL SHA256/HMAC）。
- **三服务**：statusserver（注册表/心跳摘除/token 签发校验/最小负载分配）、
  gateserver（注册/登录/限流/登录流水）、chatserver（TCP 接入/token 校验/路由表/顶号/PushToUid）。
- **SQL**：sql/001_init.sql（t_user + t_login_session）已应用 3316 实例。
- **联调**：tools/system_test/m1_flow——注册→重复 409→错密码 401→登录→TCP 登录→顶号→伪造 token 401，
  连续 5/5 PASS；单测 30/30。

### 坑位（本里程碑 6 个，全部有回归）
1. **Beast async_write 持引用不持所有权**：消息体必须活到完成回调（shared_ptr 持有），否则 UAF；
2. **递归 lambda 捕获栈上 std::function 引用**：宿主函数返回即悬垂 → 改成员函数递归；
3. **发帧与关闭的竞态**：两次独立 post 到 strand 不保证期望顺序 → 合并为单任务（sendFrameThenClose）；
4. **Windows close 丢弃在途数据**：flush 后必须 shutdown_send（FIN 跟随数据）+ 延迟 close；
   直接 close 客户端收到 RST、末帧丢失；
5. **asio::strand 写完成回调必须 bind_executor**：否则完成回调游离在 strand 外与入队逻辑并发；
6. **io_context 跑空即 stopped**：复用前 io.restart()。
- 另：salt CHAR(16)→CHAR(32)（DDL 与文档同步）；调试时 exe 被运行中进程锁定导致 LNK1168，
  曾让「已修复」的假象维持多轮——**重编前必须先杀进程**（教训：验证修复先确认二进制真的更新了）。
